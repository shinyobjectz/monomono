# __NAME__

Monorepo on [monomono](https://github.com/content-jet/monomono). Nested `AGENTS.md` files own folder rules. This file is the repo contract: how work enters the tree, and which folder owns which kind of work. It is yours; the package never rewrites it.

## Rules

- Enter the repo through `just`. Do not add parallel CLIs (`package.json` scripts, Makefiles, cargo aliases, command READMEs).
- Keep the justfile a thin router. Package recipes come from `.mono/mono.just`. Your recipes call `scripts/build`, `scripts/tools`, or `scripts/update`. No business logic in the justfile.
- Buck2 is the build graph. Anything that turns sources into an artifact, and every test, is a target in a `BUCK` file. `just build`, `just test`, and `just run` are buck2. A shell script under `scripts/build` is a temporary bridge, not a home.
- Toolchains are declared, never assumed. `toolchains/BUCK` starts with `genrule` and `python_bootstrap` only. Add one with `just toolchain add <name>`.
- Every third-party ecosystem lives under `packages/<eco>` behind an adapter. Manifests and lockfiles live there and nowhere else. `just pkg add <eco> <name>`.
- Reusable code goes in `library/`. Deliverables go in `app/`. Apps depend on library targets; they do not reach into another area's files.
- Do not write errant markdown. Allowed prose: `AGENTS.md`, Gherkin `.feature`, `feature.md`, `library.md`, `PROJECT.md`, and the root `README.md`. Everything else that is not code goes to `context/dump` via `just context put`.
- Specify a feature before building it: Gherkin in `context/projects/<project>/features/<slug>/bdd`, then a red test target, then implementation.
- Public or reusable repos are git submodules under `submodules/`. `just submodule add <url>`.
- One hidden agent folder: `.agents/`. Standing rules live here; skills are generated by `just agents sync`. Do not create `.cursor/`, `.claude/`, or `.codex/` unless a host cannot see `.agents/`.
- `.mono/` is the package and is read-only. Change behavior in your own files or upgrade with `just mono update`.

## Folders

| Path | Owns |
| --- | --- |
| `app/` | Deliverables: the things you ship. One folder per surface. |
| `library/` | Shared code. One folder per domain, each with a `library.md`. |
| `packages/` | Third-party ecosystems. Manifests, lockfiles, adapters. |
| `toolchains/` | Declared buck2 toolchains. |
| `context/` | Knowledge that is not code: the sqlite junk drawer and project features. |
| `scripts/` | Just backends: `build`, `tools`, `update`. |
| `git/` | CI source of truth. `.github/workflows` is a generated copy. |
| `submodules/` | Public or reusable repos attached as git submodules. |
| `.agents/` | Standing rules (this file) and generated skills. |
| `.mono/` | The monomono package, pinned to a release. |

Add a top-level area with `just area add <name>`. Read the nested `AGENTS.md` before editing that tree.

## Lifecycle

1. **Project** — `context/projects/<slug>`. `just context project new <slug>` if it does not exist.
2. **Spec** — Gherkin in `features/<slug>/bdd`. `feature.md` is context, not the contract. `just context feature new`, then `just context feature check`.
3. **Lock** — a red test target: `just context feature test <project> <slug> <name>`. `just test //context/...` stays red until the work is done.
4. **Implement** — in `library/` or `app/` as buck2 targets. Not in `context/`.
5. **Green** — `just check`. That is also what CI runs.

## CLI

`just` is the only entrypoint. `just` lists recipes; `just help` adds the lifecycle.

```
just setup | doctor | check
just build | test | run | targets        # buck2
just toolchain list | available | add <name>
just pkg init <eco> <adapter> | add | update | sync
just context put | get | project new | feature new|check|test
just area add <name>
just submodule add <url> [name]
just agents sync
just ci sync | run | status
just mono status | update [ref]
```

Grammar: `just <area> <verb> [args]`. Add a recipe and its script in the same change.

## Where to put work

| If you are about to… | Put it here |
| --- | --- |
| Write a thought, scrape, rule, or note that is not code | `context/dump` via `just context put` |
| Start a project | `context/projects/<slug>` via `just context project new` |
| Define what a feature must do | `context/projects/<project>/features/<slug>/bdd` |
| Lock the feature | its `test/` folder as buck2 targets |
| Add a shared module | `library/<domain>` with a `BUCK` and a `library.md` |
| Ship a surface | `app/<surface>` with a `BUCK` |
| Add a dependency | `just pkg add <eco> <name>` |
| Add a language | `just toolchain add <name>`, then `just pkg init <eco> <adapter>` |
| Change CI | `git/ci`, then `just ci sync` |
| Attach a public repo | `just submodule add` |
| Teach an agent a repeatable workflow | hand-authored `.agents/skills/<name>/SKILL.md` |
